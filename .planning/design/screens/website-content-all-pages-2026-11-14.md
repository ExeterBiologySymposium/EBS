# Website content editor for all pages

Use the current **Website content** workspace, controls and EBS styles. Keep the page selector, audience, live link, editing tabs and draft controls in their current positions. Use native option groups in the selector so 24 pages are easy to scan with a keyboard or screen reader.

| Group | Options |
| --- | --- |
| Symposium | Home, About, Team, Schedule, FAQ, Contact |
| Participation | Register, Student registration, Schools, Judges, Student research, Research projects |
| Member resources | Events, Resources, Coding, Python, R / RStudio, Open Source, Dataset library |
| Account and policies | Account, Accept invitation, EBS administration, Terms, Privacy |

Each page opens with the page heading and a set of collapsible field groups labeled to match the reader page. Repeatable content uses the editor's existing add, move, remove and Undo controls where the page supports changing the list. Large collections such as the Dataset library open one entry at a time and provide search by entry name. Give URL, alt text, schedule columns, registration destinations and other structured fields their own labels. Keep Account help grouped by who sees it and administration help grouped by workspace.

Preview uses the existing reader layouts and makes the audience or state visible where a page has multiple views. Account can preview visitor, Pending and Accepted guidance. Registration can preview the visitor view from the signed-in editor. Admin preview shows its editable headings and guidance with inert workflow controls. Use existing status messages, error summary, focus handling and mobile action bar. Include **Edit this page** shortcuts for authorized Team members in page layouts where they can access the page. The selector gives Team members direct access to every editor regardless of reader redirects or membership.
